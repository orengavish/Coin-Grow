## 2. The Game — Coin Grow

**Core idea:** An AI-generated financial literacy game for kids (8+) through adults. Players learn money concepts by *living* them — bartering in a medieval market, choosing how to spend, discovering consequences.

**The prompt is the product.** The AI prompt engine generates all lesson content: story, characters, branching paths, outcomes, debriefs. The game engine is just a delivery vehicle for what the AI writes.

**Social layer:** Classrooms compete against each other. Schools against schools. A market simulator for investment competitions is the future tier.

**Current milestone:** A working Lesson 1 — "The Orange Quest" — where a 12-year-old named Eli must barter for an orange to save his sick little brother Luca before dawn.

## 3. What a "Level" Is

A lesson in Coin Grow has this structure:

```
Cinematic Intro        → Animated story scene, sets emotional stakes
    ↓
Intro Scenes           → Prof Penny (owl mentor) introduces the concept
    ↓
Path Selection         → Player chooses how to solve the problem (3-5 options)
    ↓
    ├── Dead End Paths → Teach a micro-lesson, return to selection
    └── Live Paths     → Play through scenes, earn points
    ↓
Ending Scenes          → Resolution, consequence plays out
    ↓
Debrief                → Prof Penny explains the concept, trophy awarded
```

Each path is a mini adventure with its own scenes, NPCs, and dialogue.

The **lesson JSON** (generated by Claude AI) defines all of this. The game engine reads it and renders it. The JSON schema includes:
- `intro_scenes`, `paths`, `ending_scenes`
- Characters with bilingual dialogue (`en`/`it`)
- `scoring.path_points`, `debrief`, `trophy`

## 4. Architecture Decisions (Already Made)

| Layer | Decision | Why |
|---|---|---|
| Mobile framework | **Flutter** (Dart) | Cross-platform iOS/Android, one codebase |
| Game engine | **Flame** (Flutter plugin) | 2D game engine inside Flutter — keeps lesson UI and game world in one codebase |
| Character animation | **Rive** | Skeletal animation, state machines, small file size. Used by Duolingo. |
| Lesson content | **Claude AI** (Anthropic API) | Prompt-generated JSON lessons |
| Backgrounds | **AI-generated images** (Bing/DALL-E) | Free, fast, cartoon storybook style |
| Character sprites | **Kenney.nl** free packs (CC0) | Professional quality, pre-cut walk cycles, no cost |
| Mentor character | **Prof Penny** (owl) — 3 PNG poses exist: wave, thoughtful, celebrate | Will become Rive rig |
| State management | **Provider** | Simple, fits the lesson state machine |
| Navigation | **Go Router** | Standard Flutter routing |
| Backend | None yet — local JSON assets | API connection planned for later |

## 6. The Level Builder — Your Mission

**Goal:** Given a text description of a game scene, produce a fully playable animated 2D Flame level.

### What "a level" means in Flame terms

```
FlameGame
  └── World
        ├── Background layer      (parallax scrolling AI image)
        ├── Path layer            (bezier/waypoint path the player walks)
        ├── NPC sprites           (at stalls, placed along path)
        ├── Player sprite         (Eli, walks the path, stops at NPCs)
        ├── Interaction zones     (proximity triggers dialogue)
        └── Flutter overlay       (dialogue card, HUD, NarrativeBox)
```

### What the Level Builder Pipeline must do

```
INPUT:  Text description
        e.g. "A medieval market street. Eli walks left to right.
               Three vendor stalls: fisherman, bread baker, orange seller.
               Orange seller is at the far right."

    ↓ Step 1: AI Layout Generator
        Call Claude API with description
        Output: JSON scene layout
        {
          "background": "medieval_market_day",
          "path": [[0.0, 0.6], [0.3, 0.58], [0.7, 0.62], [1.0, 0.6]],
          "npcs": [
            {"id": "fisherman", "x": 0.25, "sprite": "vendor_male_1", "dialogue_ref": "path_fish"},
            {"id": "baker",     "x": 0.55, "sprite": "vendor_female_1", "dialogue_ref": "path_bread"},
            {"id": "orange_seller", "x": 0.85, "sprite": "vendor_male_2", "dialogue_ref": "path_orange"}
          ],
          "player_start": [0.0, 0.6],
          "interaction_radius": 0.08
        }

    ↓ Step 2: Asset Resolver
        Map sprite IDs → actual PNG/sprite sheet files from Kenney pack
        Map background → AI-generated image (or generate one via API)

    ↓ Step 3: Flame Level Builder
        Read the layout JSON
        Instantiate Flame components:
          - ParallaxComponent for background
          - SpriteAnimationComponent for each NPC (idle loop)
          - SpriteAnimationComponent for player (walk along path)
          - CircleHitbox interaction zones
          - Flutter overlay trigger on zone enter

OUTPUT: Playable Flame scene, integrated with existing lesson_player.dart
```

### What you are NOT building
- The AI prompt engine (exists)
- The lesson schema (exists)
- The dialogue/debrief UI (exists)
- The lesson state machine (exists)

You are building **the visual game world layer** that sits under the existing UI.

## 7. Key Technical Challenges

### 7.1 Flame + Flutter overlay integration
The existing dialogue cards, NarrativeBox, and Prof Penny are Flutter widgets. Flame runs as a game widget. You need to bridge them cleanly — Flame triggers events, Flutter widgets render on top.

Pattern: `GameWidget` inside a `Stack`, Flutter UI overlaid via `ValueNotifier` or `Provider`.

### 7.2 Path walking
Player walks a bezier/waypoint path automatically (not keyboard-controlled). On mobile: tap-to-walk toward interaction zone. Player stops at NPC, interaction begins.

### 7.3 Sprite sheet animation
Kenney packs come as PNG sprite sheets (e.g. 4 frames of walk cycle in a row). Flame's `SpriteAnimationComponent` handles this natively — you define frame count, frame size, FPS.

### 7.4 AI background generation
Bing Image Creator (free, DALL-E 3) generates backgrounds on demand. For the level builder, consider: generate once, save to `assets/images/`, reference by ID. Do not regenerate every run.

### 7.5 Rive (Prof Penny)
Rive is a browser design tool (rive.app). Someone needs to build the rig. The code integration in Flutter is straightforward — `RiveAnimation.asset()` + state machine controller. The bottleneck is the art, not the code.

## 12. The Meta-Game Layer

Three new aspects sit **above** the Flame game world. None change the level builder core pipeline — they are additional keys Claude generates alongside `game_world`.

### 12.1 Monitor (Teacher / Parent Dashboard)

Teachers and parents observe a student's session in real-time, inject questions at key moments, and override which path plays next.

**Builder output (added to lesson JSON):**
```json
"monitor": {
  "checkpoints": [
    {
      "after_npc": "baker",
      "teacher_can_pause": true,
      "suggested_question": "Why didn't Eli accept the first offer?"
    }
  ],
  "teacher_controls": ["pause", "override_next_path", "inject_hint"]
}
```

**Backend:** Firebase Realtime Database. Game emits checkpoint events on NPC interaction. Teacher web app (or Flutter admin screen) subscribes and renders a class map — who's at which NPC, who's stuck.

**Build order:**
1. Read-only dashboard (ship first) — teacher sees real-time progress
2. Pause / resume control
3. Override path (redirect student to a specific scene)
4. Inject hint (push a message into the student's running game)

### 12.2 Competition (Leaderboard)

Classrooms compete against each other. Schools against schools. Age groups against age groups.

**Builder output:**
```json
"competition": {
  "leaderboard_key": "lesson_01_barter_v1",
  "tiers": ["classroom", "school", "country"],
  "metric": "score_plus_time",
  "event_window": null
}
```

**Backend:** Firebase Realtime Database. One collection per `leaderboard_key`. Score submitted on lesson completion — a single write. Leaderboard queries sort by `metric`.

`event_window` is `null` for always-on lessons. For timed competitions set an ISO date range (e.g. `"2026-10-01/2026-10-07"`).

### 12.3 Events + Social Sharing

**Events** are time-gated lessons with a seasonal banner and bonus multiplier:
```json
"event": {
  "id": "harvest_week_2026",
  "active_from": "2026-10-01",
  "active_until": "2026-10-07",
  "bonus_multiplier": 1.5,
  "banner": "🎃 Harvest Week — double points!"
}
```
No extra backend. The app reads dates on lesson load. `event` is `null` when no event is active.

**Social sharing** — builder generates the template, Flutter renders to image, OS share sheet distributes:
```json
"social": {
  "result_card_bg": "market_sunset",
  "share_text": "I bartered my way to {score}/100 in The Orange Quest! 🍊 #CoinGrow",
  "platforms": ["instagram_story", "whatsapp", "tiktok"]
}
```
Implementation: `RepaintBoundary` → `toImage()` → `share_plus` package. One widget, reused for every lesson.

The AI Layout Generator (Step 1) now produces all five keys:

```json
{
  "game_world": {
    "background": "medieval_market_day",
    "path": [[0.0, 0.6], [0.3, 0.58], [0.7, 0.62], [1.0, 0.6]],
    "npcs": [ ... ],
    "player_start": [0.0, 0.6],
    "interaction_radius": 0.08
  },
  "monitor": {
    "checkpoints": [ ... ],
    "teacher_controls": ["pause", "override_next_path", "inject_hint"]
  },
  "competition": {
    "leaderboard_key": "lesson_01_barter_v1",
    "tiers": ["classroom", "school", "country"],
    "metric": "score_plus_time",
    "event_window": null
  },
  "social": {
    "result_card_bg": "market_sunset",
    "share_text": "Scored {score}/100 🍊 #CoinGrow",
    "platforms": ["instagram_story", "whatsapp", "tiktok"]

  "event": null
```

Steps 2 and 3 of the pipeline are unchanged. Asset Resolver handles `result_card_bg`. Flame Builder only reads `game_world`. The other four keys feed Firebase and the share plugin.
