🎛️ The Conductor — Streamlit Studio

Streamlit is the dashboard you open in a browser. It's the control room — you type a description and press Generate. It calls everyone else in order.

What you see

Text box → generate button → lesson preview → save button. That's it. All the complexity is hidden behind those controls.

What it does internally
  1. Calls Claude API → gets lesson JSON
  2. Calls DALL-E → gets background image
  3. Validates the output
  4. Saves to lessons/ folder

🤖 The Composer — Claude AI

Claude is the writer. It reads our AI Prompt (the IP) and writes a complete lesson in JSON. Every scene, every character, every choice.

Input

Our system prompt + lesson description + age + concept

Output — Lesson JSON
  • Intro scenes (story, characters)
  • 3–5 paths (2 dead ends + live paths)
  • NPC dialogue (bilingual EN + IT)
  • Debrief + trophy + scoring
  • Scene layout for Flame

Model: claude-sonnet-4-6 · ~2s per lesson · ~$0.03 per call

🎨 The Painter — DALL-E / Bing

The background art is AI-generated. We write a prompt describing the scene, and DALL-E paints it. We save 4 variations — the app picks one randomly each session.

Prompt we write

💃 The Dancer — Rive

wavethoughtfulcelebrate

Rive is a browser animation tool. You design Prof Penny's skeleton, add state machines, and export a .riv file. Flutter plays it with one line of code.

State Machine
idle → wave (on enter scene)
idle → thoughtful (on hint shown)
idle → celebrate (on correct answer)

⚠️ Rive requires a human to design the rig — it's a GUI tool, not code. Today we use PNG + bobbing animation. Rive is the upgrade.

Free tier at rive.app. Community rigs at rive.app/community. Search "owl" for free starting points.

🎮 The Stage — Flutter + Flame

Flutter handles all UI — text, buttons, menus. Works anywhere: iOS, Android, Web, Windows.
Flame handles the game world — sprites, movement, physics, camera. Sits inside Flutter as a widget.
Bridge — when Flame detects "player entered NPC zone", it fires an event. Flutter catches it and shows the dialogue overlay.

⭐ The Score — The AI Prompt

This is the heart of the product. The prompt is what makes every lesson emotionally powerful and pedagogically correct. This is the IP.

SYSTEM — COIN GROW LESSON ENGINE v0.2 ══════════════════════════════════════════════════════════ WHO YOU ARE You write financial literacy lessons for children and adults. Your output is a complete playable lesson in JSON format. You are not a teacher. You are a storyteller. THE THREE UNBREAKABLE RULES 1. FEEL BEFORE UNDERSTAND The player must feel the problem before they understand the concept. Eli doesn't learn about barter theory. He needs an orange NOW OR HIS BROTHER DIES. Emotion first. Concept second. Always. 2. CONSEQUENCE IS THE TEACHER Wrong choices do not punish. They teach. Every dead end has a micro-lesson: "Here's why that didn't work. Now you know." The game respects the player's intelligence. 3. EMOTION ANCHORS MEMORY Abstract concepts bounce off children's brains. Emotional stories stick for life. Money is not explained — it is felt as the solution to an impossible problem. THE LESSON FORMAT ────────────────────────────────────────────────────────── { "lesson": { title, concept, emotional_hook, age_group }, "world": { setting, time_period, atmosphere }, "characters": { "player": { name, age, personality, gives, needs }, "owl": { name: "Prof Penny", role: "mentor" }, "npcs": [ { id, name, needs, gives, dialogue_style } ] }, "intro_scenes": [ scene, scene, ... ], "paths": [ { "id": "trade_fish", "is_dead_end": false, "card": { label, effort, time_estimate, visible_reward }, "scenes": [ ... ], "outcome": { en: "...", it: "..." } }, { "id": "beg_seller", "is_dead_end": true, "dead_end": { "micro_lesson": { en: "Begging isn't trade...", it: "..." }, "owl_response": { en: "Prof Penny says...", it: "..." } } } ], "ending_scenes": [ ... ], "debrief": { concept_name, summary, real_world_connection }, "scoring": { path_points, max_points } } SELF-VERIFY BEFORE OUTPUTTING ────────────────────────────────────────────────────────── [ ] Does the opening make the player feel something in 10 seconds? [ ] Is every dead end a real lesson, not just a failure? [ ] Is the concept never explained — only experienced? [ ] Do all leads_to_scene IDs point to real scene IDs? [ ] Does max_points equal the highest scoring path? [ ] Is all dialogue written in both EN and IT? [ ] Would a child feel something reading this?

Why the Prompt Is the IP

🔐

Anyone can build a game app

Flutter, Flame, Rive — these are open source tools. Any developer can set them up in a day.

⭐

Only we have this prompt

The pedagogical principles — Feel Before Understand, Consequence Is The Teacher, Emotion Anchors Memory — took research, iteration, and testing to develop. That's the moat.

⚡

It scales infinitely

One prompt → unlimited lessons. Barter, money, saving, investing, tax, insurance — all generated from the same engine.

Prompt versioning rule

Prompts live in prompts/lesson-generator-v0.2.md.
Never edit in place. Always copy to the next version number.
v0.1 → v0.2 → v0.3...

💡 The prompt is versioned like code. Every improvement is tracked. Bad changes can always be rolled back.

Matrix · Quests · Badges

Three systems built on top of the existing pipeline — no new tools required

🧮

The Matrix

Junior defines axes (locations × items × characters) before generation. Each active cell becomes an NPC zone in Flame. Different lessons = different axes. Claude fills the content.

Locations Items Characters
🗺️

Quest System

Mandatory quests (story, required) + optional quests (exploration, bonus points). Optional quests are discovered by entering NPC zones — not pre-announced. Exploration is its own reward.

✅ Mandatory ⭐ Optional
🏆

Badges + Trophies

Badges for specific actions (🗺️ Explorer, ⚡ Speed, ✨ Perfect, 🔗 Chain). Trophy tiers per level: 🥉→🥈→🥇→💎. Shown on result card, profile, and leaderboard.
